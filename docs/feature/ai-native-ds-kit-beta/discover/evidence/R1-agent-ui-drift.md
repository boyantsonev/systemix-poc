## How to read the table

Quote status code at the start of each quote-or-paraphrase cell:
- Q2 = wording returned identically by two separate fetches of the page.
- Q1 = wording returned by one fetch (or one fetch plus an overlapping search snippet).
- QS = wording seen only in a WebSearch extract (page unreachable, not fetched).
- P = paraphrase (wording not verifiable); strength is capped at S2.
Every quote is 25 words or fewer. WebFetch passes the page through a summarising model, so Q1/Q2 are "as returned by the tool", not byte-checked against raw HTML. Foreign-language and typo'd originals are kept as shown.

Grades: PAST_BEHAVIOR (lived, with specifics), PRESENT_PAIN (ongoing, no specifics), FUTURE_INTENT_OR_OPINION (discounted), DISCONFIRMING (problem small, already solved, or not worth paying for).
Strength: S1 weak, S2 medium, S3 strong. "Date" is the date as shown on the page; "not shown" means the extract carried no date.

## Verdicts

H1 (agent-built UI drift felt weekly, no system for it): SUPPORTED IN SUBSTANCE, WITH THREE CAUTIONS.
- Supported: agents hardcode values against explicit rules (R1-01), choose the wrong component library (R1-10), rebuild components instead of reusing them (R1-14), improvise past design handoffs (R1-09), propose from-scratch redesigns of shipped apps (R1-06), and default to generic looks (R1-11, R1-21). Quantified cases: 3 of 4 consumer repos drifted (R1-03); 594 raw button usages (R1-04) and about 139 hardcoded palette classes across 30 files (R1-08) are agent-era repos but the issues do not name the agent as the cause.
- Caution 1, "weekly" is NOT evidenced. Cadence appears only in R1-05 (a weekly manual sync) and R1-07 (11 pages added without audit; mirror 5 weeks stale). Nobody states a weekly drift rhythm.
