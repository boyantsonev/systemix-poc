---
title: Getting started
description: Install the plugin, set up your design system, and run your first check.
---

You need Claude Code and a repo with a web UI (or none yet: setup can start from an interview).

## 1. Install the plugin

In Claude Code, one line at a time:

```
/plugin marketplace add boyantsonev/systemix-poc
/plugin install systemix@systemix
```

No account, no key, nothing to configure.

## 2. Set up your design system

```
/systemix:setup
```

Setup looks at your repo and picks where to start: from the code you already ship, from a short
interview when there is no UI yet, or from a Claude Design output. It proposes four files in
`design/`, and writes each only after you say yes:

```
design/
  DESIGN.md        the design system in words: principles, patterns, voice
  tokens.css       the tokens, canonical in code
  guardrails.mdx   the rules, explained
  rules.md         every rule as a row an agent can check
  evals/rules/     one sample of bad work per scripted rule
```

Then make the rules yours: replace the starter rows with your brand's voice, legal lines and
patterns. Setup runs `systemix rules eval` until every sample of bad work is caught.
[How rules work →](/docs/concepts/rules)

## 3. Check something

```
/systemix:check src/components
```

You get **fail**, **pass with flags** or **pass**, and every problem with its rule ID, where it is
and the fix. Add `--score` for your AI-readiness score out of 100.

## 4. Build the next thing with a brief

Before the next screen or component:

```
/systemix:brief a settings page for notifications
```

One screen: the rules that apply, the components and tokens to start from, and what was already
decided. Build, then run `/systemix:check` before review.

## 5. Run a goal as a loop (when you're ready)

```
/systemix:loop open make sign-up take under two minutes
```

The goal gets evals, then pictures, a prototype, code and a release, with a gate at each step
that only you rule on. Start small: a visible drift fix exercises every part, end to end.
[How the loops work →](/docs/concepts/loops)

## Without Claude Code

The scan behind the commands is also a CLI:

```sh
npx @getsystemix/cli rules init           # the starter rules.md
npx @getsystemix/cli rules check src      # pass, flags or fail
npx @getsystemix/cli audit report --dirs src   # the readiness score and report
```

[The CLI reference →](/docs/reference/cli)
