---
title: What is Systemix?
description: The design system agent for AI-native products, as a free Claude Code plugin.
---

Systemix is the design system agent for AI-native products. It sets up your design system as
files in your repo, gives your agents its rules before they build, checks their work against
those rules, and runs every change from a goal to a shipped, measured result. **You approve every
step that matters.**

It is a free, open-source (MIT) Claude Code plugin with four commands. Everything runs on your
machine; nothing is sent anywhere.

## The four commands

| Command | When | What you get |
|---|---|---|
| [`/systemix:setup`](/docs/commands/setup) | Once, to start | `design/`: your design system and `rules.md`, from your code, an interview, or Claude Design |
| [`/systemix:brief`](/docs/commands/brief) | Before you build | The rules that apply, what to start from, what was already decided |
| [`/systemix:check`](/docs/commands/check) | Before review | Pass, pass with flags or fail, rule by rule, with the fix; `--score` for the readiness score |
| [`/systemix:loop`](/docs/commands/loop) | To run a goal | A goal to shipped and measured, stopping at every gate for you |

## Why it works

Design rules end up in five places at once: a brand wiki, a design file, a `DESIGN.md`, the
token file, and the prompts inside every AI tool. They drift, and an agent briefed from the wrong
copy ships the old look. Systemix keeps **one master that a machine can read**:
[`design/rules.md`](/docs/concepts/rules), where every rule is a row with a test. Every command
reads it fresh, and drift is found and fixed in small, checked loops.
